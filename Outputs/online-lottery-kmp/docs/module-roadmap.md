# 功能模块落地顺序

## 当前基线

客户端已具备大厅、比赛、数字彩选号、开奖、个人中心、主题设置等页面。赛事和开奖查询已有少量外部数据接入；登录、实名、钱包、订单、出票、结算、提现及消息仍以演示交互为主。

后端首版已建立 Spring Boot 服务、PostgreSQL/Flyway 基线、模块状态接口和彩种目录接口。下面按资金和业务依赖顺序推进。

| 阶段 | 模块 | 本阶段交付 | 验收重点 |
| --- | --- | --- | --- |
| P0 | 基础设施 | 配置、迁移、错误码、请求追踪、审计、安全基线 | 可重复部署；秘密不入库；迁移可回放 |
| P1 | 用户与认证 | 手机登录、刷新令牌、设备管理、实名和年龄校验 | 令牌可撤销；敏感字段加密；未实名禁止投注 |
| P1 | 彩种与赛事 | 彩种、玩法、期次、赛事、球队队徽、盘口和赔率快照 | 比赛日和时区正确；停售后不接受订单 |
| P2 | 投注与订单 | 试算、幂等下单、订单列表/详情、取消、状态轨迹 | 客户端重试不重复扣款；服务端重新计价 |
| P2 | 钱包与支付 | 账户、双录分录、充值、余额、资金明细 | 任意时点借贷平衡；回调重复不重复入账 |
| P3 | 出票 | 渠道适配、重试、官方票、失败解冻 | 截止时间保护；部分出票可追踪可退款 |
| P3 | 开奖与结算 | 开奖入库、赛果确认、结算、派奖、退款 | 同一订单只能结算一次；派奖幂等 |
| P4 | 提现与风控 | 银行卡、提现审核、限额、自我排除、风险事件 | 高风险操作人工复核；完整审计证据 |
| P4 | 消息与运营 | 站内信、Push、优惠券、帮助中心、管理后台 | 消息去重；运营操作有审批和审计 |

## API 约定

- 公开接口：`/api/v1/public/**`，只提供彩种、赛事、开奖等不含用户隐私的数据。
- 用户接口：`/api/v1/**`，使用短期访问令牌；刷新令牌只保存哈希并绑定设备。
- 创建类请求必须携带 `Idempotency-Key`，服务端再叠加用户 ID 形成唯一约束。
- 金额字段统一以 `...Cents` 命名；时间字段统一为带时区的 ISO-8601。
- 赔率提交时保存快照 ID 和接受值，服务端在截止时间前再次验证。

## 第一批可用接口

- `GET /actuator/health`：服务与数据库健康检查。
- `GET /api/v1/public/lottery-games`：从数据库读取启用的彩种目录。
- `GET /api/v1/public/modules`：查看后端模块落地状态与能力范围。

后续每完成一个阶段，就将客户端对应的演示数据替换为仓储接口；不在 Compose 页面里直接发请求或拼装业务状态。
